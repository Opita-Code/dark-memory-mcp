## 1. Why this spec exists

Per atomic mirror row 2706 audit (Sesión 4, 2026-10-14), vibe-loop-git has a gap
between "library built" and "operational runtime". The 6-phase protocol
(OSINT → SPEC → ARTIFACT → DRIFT_JUDGE → RESOLVE_DRIFT → ATOMIC_MIRROR)
is documented in `mods/vibe-loop-git/SKILL.md:118-127`. Operators / agents
execute it manually today by reading the mod and calling
`vibe_spec`, `vibe_publish`, `resolve_drift`, `agent_memory_save` in order.

The operator (2026-10-14, post-2706) chose **B + D combined**:
- **(B) compiler**: a new wire tool that converts a `vibe_spec` into a
  bash script the operator (or agent) can execute to drive the loop.
- **(D) enricher**: honesty fields added to `vibe_publish` /
  `vibe_spec` responses WITHOUT behavior change — the mod-approved
  path for Loop 8-13 primitives per `mod.json:56`.

Both choices respect SKILL.md:59 ("Not auto-executing — every loop requires
operator approval").

---

## 2. What this spec is NOT

- NOT a fully autonomous driver (would violate operator approval).
- NOT wiring Loop 8-13 primitives into routing/decisions (would violate
  `mods/vibe-loop-git/mod.json:56` "instrument → measure → decide → flip").
- NOT replacing existing `vlp_handle_event` (the state-machine driver
  in `internal/vlp/usecase.go` keeps its current passive role).

## 3. Architecture decisions

### 3.1 Compiler output = bash + jq (binary-portable, no external deps)

A `dark_memory_vibe_compile(loop_id, spec_id, options)` tool returns a bash
script that:

1. Resolves context (reads `vibe_spec` from `dark.db`)
2. Outputs the 6 phases as numbered bash functions:
   `phase_osint`, `phase_spec`, `phase_artifact`, `phase_drift_judge`,
   `phase_resolve_drift`, `phase_atomic_mirror`
3. At each transition boundary, calls a sentinel
   `__dark_mem_pause_for_approval` function that pauses the script and
   surfaces the current state. Operator decides continue / revise / abort.
4. On completion, calls `dark_memory_agent_memory_save` to write the
   atomic mirror row.

Output format:

```bash
#!/usr/bin/env bash
# Generated by dark_memory_vibe_compile (loop=N, spec_id=...)
# Operator approval gates built in. Edit at your own risk.
set -euo pipefail

phase_osint() { echo "[Phase 1] OSINT — run dark_research_topic via mcp_call ..."; ... }
phase_spec() { echo "[Phase 2] SPEC — already created via vibe_spec(spec_id=$spec_id)"; ... }
phase_artifact() { echo "[Phase 3] ARTIFACT — produce <file>"; ... }
phase_drift_judge() { echo "[Phase 4] DRIFT_JUDGE — call vibe_publish artifact_ref=..."; ... }
phase_resolve_drift() { echo "[Phase 5] RESOLVE_DRIFT — aligned accept, drift_detected revise, needs_human stop"; ... }
phase_atomic_mirror() { echo "[Phase 6] ATOMIC_MIRROR — call dark_memory_agent_memory_save ..."; ... }

__dark_mem_pause_for_approval() {
  local phase="$1"
  echo "=== Approval gate at phase $phase ==="
  echo "Continue? [y/n/revise/abort]: "
  read -r choice
  case "$choice" in
    y|yes) return 0 ;;
    n|no|abort) exit 1 ;;
    revise) echo "revise mode — operator handles manually"; exit 2 ;;
    *) __dark_mem_pause_for_approval "$phase" ;;
  esac
}

main() {
  phase_osint; __dark_mem_pause_for_approval 1
  phase_spec; __dark_mem_pause_for_approval 2
  phase_artifact; __dark_mem_pause_for_approval 3
  phase_drift_judge; __dark_mem_pause_for_approval 4
  phase_resolve_drift; __dark_mem_pause_for_approval 5
  phase_atomic_mirror
}

main "$@"
```

**Design rationale**: bash + `set -euo pipefail` is the universal ground
truth. No new binary needed. The script is the artifact — auditable,
diff-able, replay-able. The MCP calls inside use `mcp_call` (a thin
shim that does JSON-RPC over stdio to the running `dark-mem-mcp.exe`).

### 3.2 Enricher fields (no behavior change)

Fields added to `vibe_publish` / `vibe_spec` response payloads. They are
**observability only** — never consumed by routing or decision logic.

| Field | Source | Used by | Phase |
|---|---|---|---|

| `confidence_caveat` | already in vibe_publish (L11.2 SHIPPED) | orphan-stable | shipped |

**Design rationale**: per mod.json:56 — fields sit on the wire response,
no one reads them yet, but data is captured. After 2 weeks of
production, the same fields can be promoted to decision inputs via a
separate spec with operator signoff (the "flip" step).

### 3.3 Where the compiler lives

New file: `internal/tools/vibe_compile.go`. New wire tool:
`dark_memory_vibe_compile`. Schema is light:

```json
{
  "spec_id": "<integer>",
  "options": {
    "format": "bash" | "ps1" | "json",
    "include_osint": true | false,
    "include_artifact_template": true | false
  }
}
```

Default: `format=bash`, `include_osint=true` (the OSINT phase uses
`dark_research_topic` calls baked in), `include_artifact_template=true`.

### 3.4 Where the enricher lives

Modifications to `internal/tools/vibe.go`:
- `vibe_spec` handler returns the spec fields as today PLUS the new
  `operator_status`, `cost_summary`, `economy_delta` fields with their
  zero values.
- `vibe_publish` handler already returns `confidence_grade` +
  `confidence_caveat` per Phase 21. Add `task_class_label` (a copy
  of `task_class` for visibility in the publish path) + the same 3
  enricher fields.

The enricher fields use the existing `internal/vibeflow/*.go` packages
(`operatorstatus.go`, `cost.go`, `economy.go`).

## 5. Operator-visible risks

| Risk | Severity | Mitigation |
|---|---|---|
| `dark_memory_vibe_compile` becomes a foot-gun (auto-runs the loop) | LOW | Return bash, never execute. Operator runs the bash script themselves. |
| Bash template injection (spec_id or text containing shell metacharacters) | MEDIUM | Use Go text/template with `printf %q` for variable insertion. Audit via linter. |
| Enricher fields confused with decision inputs | MEDIUM | Fields named with `_hint` suffix to signal "observability only". Add comment in handler "DO NOT consume in routing". |
| Compile output changes after first deploy | LOW | Cache compiled scripts by spec hash. Operator can `dark_memory_vibe_compile` repeatedly; output is deterministic. |
| vibeflow package adds 5-10 MB to cold-start | LOW | Already loaded for the `task_class` ADVISORY (Phase 21). Marginal increase. |
